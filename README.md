# FIS — Forest Information System content repo

Structured legal-content repository behind the FIS PWA (Tanzania Forest Act, Cap. 323
and the Forest Regulations made under it). Regulations live here as data; the build
turns them into the exact data block the PWA consumes, plus an offline single-file app.

> **Status: SKELETON.** The structure, conventions and CI are in place; the content
> (instruments, provisions, cards, sources) is pushed in follow-up commits.
> CI is expected to be red (`continue-on-error`) until the content lands.

## Structure

```text
content/
  meta.json                     PWA meta + chain registry, card counts, verification policy
  sources.json                  formal source registry (chain of instruments)
  scenarios.json                PWA scenarios
  cards/order.json              canonical card order, exactly as emitted to the PWA
  cards/{act,gn153,gn417}/      one JSON file per card id (a*, r*, g*)
  gn-153-2004-transcript.md     cleaned OCR transcript of the GN 153/2004 scan
  instruments/<id>/instrument.json   metadata + amendment events per instrument
  instruments/<id>/provisions.json   full text, provision by provision
source-evidence/                retrieved official texts, OCR transcripts, checksums
build/build.js                  validates content, emits dist/ + releases manifest
tests/                          node --test suites (schema, amendment, consolidation, references)
app/index.html                  PWA shell; build inlines the data at the id="data" script
dist/, releases/                generated by build (gitignored)
```

## Chains

- **Chain A** — principal: GN 153 of 2004 (Forest Regulations, 2004; published
  21/5/2004; 59 regulations, 39 schedules). Amendments: GN 1132/2011, GN 324/2015,
  GN 255/2017, GN 59/2022, GN 132/2025 (current rate table).
- **Chain B** — principal: GN 417 of 2019. Amendments: GN 657/2019, GN 255/2023.

GN 255 of 2017 and GN 255 of 2023 are **different instruments** that share a notice
number. Both carry a `nameCollisionWarning`.

## Conventions (the contract)

- **Full legal text is the foundational layer.** Every instrument keeps its own
  provisions; amendment events live in the amending instrument's `instrument.json`,
  and replacement provisions live in the amending instrument's `provisions.json`,
  never edited into the principal.
- **Nothing is inferred.** Publication, commencement and effective dates are distinct
  fields; `commencement` is `null` unless the instrument states it; `published` is
  `null` when unverified.
- **Missing text is explicit.** A provision absent from a scan has `text: null` and a
  note. Uncertain transcripts keep their original wording with a degraded-OCR status;
  text is never reconstructed.
- **Every provision and instrument carries a `verification` object** with a `status`
  (`verified-against-official-pdf`, `unverified-transcript`, `unverified-degraded-ocr`,
  `unverified-from-pwa`, `unverified`) and a `needsCheckAgainst` pointer.

Full schema docs and the "adding a new amendment" recipe: see `content/README.md`.

## Running

```bash
node --test tests/
node build/build.js
```

Outputs: `dist/fis-data.json`, `dist/index.html` (offline single-file app),
`releases/content-manifest.json` (SHA-256 of every content file).

CI runs both on every push once content exists.
